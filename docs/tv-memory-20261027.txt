Desarrollo exclusivo .185. Fire .190, Movistar HLS, La Sexta. No despliegue,
publicación ni cambio de servidor, canales, claves o reproducción.

Causa de asignaciones demostrada
La precarga pública FanartRepository leía el índice completo. Por cada programa
volvía a normalizar el mismo nombre de canal, compilaba String.matches para el
identificador y creaba varios Matcher nativos ICU para limpiar canal/título.
Una sonda temporal de métodos confirmó pool-17-thread-1 dentro de esas funciones,
coincidiendo con recuperación de memoria. No se conservan la sonda ni su llamada.
Esto demuestra trabajo y asignaciones evitables; no demuestra por sí solo que
cada pico de layout proceda exclusivamente de este lector.

Corrección retenida
- ReadKeys local a cada lectura, LRU de512 nombres, resultados canónicos idénticos.
- Identificador ASCII validado con límites y caracteres exactos, sin regex nativa.
- Limpieza: lower ROOT, NFD cuando es necesario y conservación de ASCII a-z/0-9.
  Eliminar marcas y después todo lo no ASCII equivale a este filtro; no se cambian
  reglas de episodios, calidad, alias, ventanas horarias o ambigüedad de imágenes.
- Marcador DRBEP.fanartRead para futuras medidas puntuales.

Errores de instrumentación y límites
-b32768 de atrace es POR CPU: reserva hasta128MiB en este Fire. La captura ampliada
agravó la memoria e hizo la prueba intrusiva; sus tiempos se descartan para afirmar
rendimiento normal. Hubo un FinalizerWatchdog durante esa fase.
-b512 perdió eventos; no usar el frame pequeño aparente como mejora.
Con -b2048 se conserva la ventana de entrada, pero sigue habiendo instrumentación.
En small-candidate2 hubo pérdida ANTERIOR a la entrada; todos los CPU conservaban
al menos7,3s anteriores al primer toque y ambos eventos táctiles estaban presentes.
No extrapolar las comparaciones de una sola muestra a toda la sesión.

Las comparaciones pequeñas provisionales mostraron ahorro en algunas muestras,
pero otras variaron y no acreditan una mejora uniforme. La medida gfx-final1
correspondía aún a Inicio y se descarta como entrada a TV. Se verifican capturas
antes/después y se prefieren gfxinfo reset/framestats sin atrace.
gfx-final-actual1 sí corresponde a En directo:766,136ms de frame,639,188ms
de hilo UI transcurrido. Es una observación, no un par de control equivalente.
